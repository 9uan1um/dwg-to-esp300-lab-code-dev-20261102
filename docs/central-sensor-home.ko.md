# 중앙 원점 센서를 이용한 스테이지 중앙 정렬

영문 문서: [Central sensor home](central-sensor-home.md)

`Center (sensors)`는 각 스테이지에 설치된 중앙 원점 센서를 찾아 이동하는 기능입니다. 버튼은 다음처럼 배치되어 있습니다.

| 왼쪽 | 오른쪽 |
|---|---|
| `Home (0, 0, 0)` | `Center (sensors)` |
| `Set local home (here = 0)` | `Go to local home` |

기존 `Home (0, 0, 0)`은 현재 로컬 좌표의 원점으로 이동하는 기능이며, 원점 센서를 탐색하지 않습니다.

| 탐색 순서 | 프로그램 축 / 제어기 채널 | 스테이지 모델 | ESP300 원점 탐색 방식 |
|---|---|---|---|
| 1 | X / 1 | M-ILS150PP | 모드 1: 원점 센서와 엔코더 인덱스 사용 |
| 2 | Y / 2, **실제 수직축** | UTS100PP | 모드 2: 원점 센서만 사용. 엔코더 없음 |
| 3 | Z / 3 | GTS150 | 모드 1: 원점 센서와 엔코더 인덱스 사용 |

이 기능은 양쪽 끝단을 왕복하지 않고 제조사가 지정한 중앙 원점을 탐색합니다. 이 원점은 스테이지의 중앙 기준이며, 장착물 때문에 제한된 이동 범위나 사용자가 설정한 소프트웨어 제한 범위의 중점을 측정하는 기능은 아닙니다.

## 사용 전 준비

새 기능을 반영하려면 **Python 웹 서버를 재시작한 뒤 브라우저 페이지를 새로고침**해야 합니다. 브라우저 새로고침만으로는 실행 중인 서버 코드가 바뀌지 않습니다. 기능 구현 당시 기존 서버는 재시작하지 않았습니다.

최초 확인은 `Dry run (no hardware)`을 체크한 상태에서 진행할 수 있습니다. 드라이런에서는 원점 탐색을 시뮬레이션하며 장비에 시리얼 명령을 보내지 않습니다.

## 사용 순서

1. **가공 경로 실행, 초점 스캔, survey를 모두 종료합니다.** 자동 초점의 `Active`도 해제합니다. 레이저는 별도로 꺼야 합니다. 이 기능은 실제 레이저 전원을 확인하거나 차단하지 않습니다.
2. **각 축의 현재 위치부터 중앙 원점까지 이동할 경로를 확인합니다.** 특히 수직 Y축, 시료 홀더, 대물렌즈, 브래킷과 케이블이 서로 간섭하거나 당겨지지 않아야 합니다. 기존 도면 영역의 Jog 제한으로 원점 탐색 경로가 정해지는 것은 아닙니다. 제어기 자체의 이동 제한은 유지됩니다.
3. **Jog를 연결합니다.** 시뮬레이션하려면 `Dry run (no hardware)`을 체크하고 `Connect`를 누릅니다. 실제로 이동할 때만 체크를 해제하고 연결합니다. 연결 자체로 원점 탐색이 시작되지는 않지만, 실제 연결은 모터를 활성화합니다.
4. **`Center (sensors)`를 누르고 확인창을 읽은 뒤 실행합니다.** X → Y → Z 순서로 한 축씩 탐색합니다. 네 버튼 아래에 현재 축과 완료한 축 수가 표시됩니다. 탐색 중에는 다른 이동 조작이 차단됩니다.
5. **세 축의 완료를 확인합니다.** 성공하면 화면의 로컬 좌표가 모두 0이 됩니다. 제어기에 설정된 원점 좌표(`SH`)는 유지하고, 탐색 후 읽은 실제 제어기 좌표를 프로그램의 새 좌표 오프셋으로 사용합니다. 기존 시료 정렬과 초점 기준은 초기화됩니다.
6. **가공 전에 시료를 다시 정렬하고 `Set local home`을 지정합니다.** 이 등록을 다시 하기 전까지 경로 실행은 차단됩니다. `Set local home`의 확인창에 표시되는 도면 중심 X/Y와 초점 Z가 의도한 값인지 확인합니다.

각 축의 탐색 제한 시간은 **300초**입니다. 오류나 시간 초과가 발생하면 이후 축의 탐색은 시작하지 않습니다.

## 실행 전 자동 확인 항목

실제 연결에서는 어느 축도 움직이기 전에 다음 조건을 세 축 모두 확인합니다.

- 연결된 스테이지 모델이 위 표의 모델과 일치하는지
- 명령 단위가 mm인지
- 모터가 활성화되어 있고 축이 정지해 있는지
- 원점 탐색 속도가 유효한지
- 원점 좌표(`SH`)가 제어기 소프트웨어 이동 제한 안에 있는지
- 하드웨어 제한(`ZH`)과 소프트웨어 제한(`ZS`)의 감시 및 제한 도달 시 이동 중단 설정이 활성화되어 있는지
- 제어기 오류가 남아 있지 않고 조회 응답이 유효한지

하드웨어 제한 감시와 제한 도달 시 중단 기능은 이미 켜져 있어야 합니다. 소프트웨어 제한 감시만 꺼져 있는 경우(이 장비에서 확인한 `ZS=4H`), 사용자가 확인한 Center 실행은 세 축의 현재 위치·원점·기존 `SL/SR` 범위를 먼저 검증한 뒤 감시 비트만 켭니다(`4H → 5H`). 설정을 다시 읽어 성공을 확인한 후에만 탐색합니다. 다른 조건을 만족하지 않으면 오류를 표시하고 탐색을 거부합니다. 제한 범위를 확대하거나 보호 기능을 끄지는 않습니다.

켜진 감시 기능은 작업 후에도 유지합니다. 비휘발성 저장 명령은 보내지 않으므로 전원을 껐다 켜면 이전 설정으로 돌아갈 수 있으며, 다음 Center에서 다시 검증합니다.

### Center 다음 Home이 움직이지 않는 경우

Center가 완료되면 그 센서 위치가 로컬 `(0,0,0)`이 됩니다. 바로 Home을 누르면 같은 위치이므로 이동이 필요하지 않습니다. 이제 이 경우 `Already at local (0, 0, 0); no move needed`를 표시합니다. 복귀 이동을 확인하려면 Jog로 원점에서 조금 이동한 뒤 Home을 누릅니다. 명령을 보냈다는 것만으로 도착했다고 표시하지 않습니다.

재연결은 소프트웨어 좌표 오프셋을 초기화하므로 비교 조건이 달라집니다. 새로고침 후 연결 입력란은 서버의 실제 포트와 Live/Dry run 모드를 반영합니다.

## 속도와 완료 판정

탐색 중에는 원점 탐색의 고속 구간을 **최대 1 mm/s**, 저속 구간을 **최대 0.1 mm/s**로 제한합니다. 기존 설정이 더 느리면 그 값을 유지합니다.

성공적으로 완료하면 기존 `OH`, `OL`, `OM` 설정을 복원합니다. 제어기의 비휘발성 메모리에 설정을 저장하는 명령은 보내지 않습니다.

완료 판정에는 다음 조건을 사용합니다.

- 제어기의 이동 완료 응답이 `MD? = 1`
- 제어기 오류 없음
- 읽은 위치가 원점 좌표(`SH`)에서 0.01 mm 이내

여기서 0.01 mm는 원점 좌표가 정상적으로 부여되었는지 확인하는 허용차입니다. 중앙 정렬의 절대 정확도를 보증하는 수치는 아닙니다.

## 중단과 오류 발생 시

**중앙 원점 탐색 중 `STOP`을 누르면 이동 중단 명령(`AB`)을 보내고 모터 유지력은 유지합니다.** 수직 Y축도 포함됩니다. 중앙 원점 탐색 이외의 기존 E-STOP 동작은 그대로입니다.

탐색이 중단되거나 실패하면 해당 좌표 기준을 신뢰하지 말고, 원인을 확인한 뒤 다시 연결하여 원점 탐색을 반복합니다. 일부 축만 완료된 상태를 세 축 전체의 중앙 정렬 완료로 판단하면 안 됩니다.

중단 후에는 낮춘 탐색 속도나 선택한 탐색 모드가 제어기에 남을 수 있습니다. 제어기가 아직 정지 중일 가능성이 있을 때 설정 복원 명령을 보내지 않기 때문입니다. 다음 탐색 전에 설정을 확인합니다.

통신이 끊기면 프로그램이 중단 명령을 전달했는지 보장할 수 없습니다. 이 경우에는 **제어기 본체의 정지 수단을 사용합니다.**

## 검증 범위

2026년 10월 27일, 실제 장비 없이 다음 항목을 모의 제어기로 검증했습니다.

- 축별 탐색 모드와 실행 순서
- 이동 전 세 축의 설정 확인 및 잘못된 설정에서의 실행 거부
- 드라이런의 시리얼 명령 미전송
- 실제 실행에 대한 명시적 확인
- 초점 스캔·survey·가공 경로와의 동시 실행 차단
- 시간 초과, STOP, 위치 확인, 통신 장애 처리
- 느린 기존 속도 유지, 시료 정렬 초기화, HTTP 요청 처리

기존 통신 테스트를 포함한 **25개 테스트가 통과**했습니다. 장비와 카메라 연결을 차단한 별도 미리보기에서도 중앙 정렬 시뮬레이션 완료와 버튼의 2×2 배치를 확인했습니다. **실제 ESP300 연결이나 스테이지 이동으로 검증한 결과는 아닙니다.**

개발용 테스트는 프로젝트 폴더에서 Python 3.12 환경으로 실행합니다. 아래 명령은 중앙 정렬을 실제로 실행하는 명령이 아닙니다.

```powershell
& .\runtime\python.exe -m unittest test_sensor_home test_esp300_bridge -v
node --check visualizer/app.js
```
