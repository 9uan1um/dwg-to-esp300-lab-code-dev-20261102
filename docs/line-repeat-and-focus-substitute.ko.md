# 직선 반복 및 초점 신호 대체 시험 — 2026-10-28

개발 복사본에서 실제 ESP300을 연결하고 브라우저 버튼과 페이지 내부 확인창으로 이동·실행·정지·재개를 수행했다. 원본 주요 소스의 해시는 복사 시점과 동일하다. 레이저 OFF는 사용자가 확인한 조건이며, 프로그램이 레이저 출력을 계측한 것은 아니다.

## 2. 초점 모듈 대체 시험과 발견한 문제

카메라/레이저 대신 raw Z=+0.020 mm에서 최대가 되는 합성 밝기 신호를 넣었다. **가짜인 부분은 광학 측정값뿐이며, 기존 FocusScanner, 실제 Z축 이동, Home/복귀, Run 실행 코드는 그대로 사용했다.** 시험 서버는 8775였고 일반 개발 서버는 연결을 해제하여 제어기를 동시에 소유하지 않게 했다.

첫 시험에서 실패를 발견했다. ±0.05 mm, 0.01 mm 간격의 탐색이 정답 +0.020 mm 대신 -0.04298 mm 보정량을 기록했다. 종료 후 local Z도 약 +0.05518 mm로 어긋났다. 로그에는 `3PA-0.020400`, `3PA-0.030350` 등 동일 목표가 연속 전송된 흔적이 있다.

원인은 초점 이동과 위치 폴링 사이의 동기화였다. 기존 코드는 `이동거리/속도 + 대기시간` 뒤에 이동이 끝났다고 가정하고, 다음 상대 이동을 캐시된 raw 위치에 더했다. 짧은 초점 단계가 위치 갱신보다 빠르면 이전 위치를 다시 사용한다. 그런데 초점 offset은 요청한 모든 이동량을 누적하므로 실제 이동과 좌표 기준이 서로 달라진다.

개발본에서 다음을 수정했다.

- 초점 스캔 시작의 실제 TP를 기준으로 각 단계의 절대 목표를 계산한다.
- 각 단계에서 MD=1 및 새 TP의 목표 도착을 확인한 뒤 밝기를 측정한다. 도착 확인 허용차 0.001 mm는 제어기 응답 검사용이며 실제 광학/기계 정밀도 보장이 아니다.
- 스캔 중 Home·Jog·Run 등의 충돌 동작은 서버에서 거부하고 화면에서 비활성화한다.
- 오래된 카메라 프레임을 새 측정으로 받아들이지 않도록 시간 초과 오류를 낸다.
- 자동초점 활성 상태를 같은 값으로 재요청할 때 비재진입 lock을 다시 잡아 응답이 멈추던 문제를 수정했다. 관련 상태 취득의 lock 순서도 정리했다.

기존 무중단 4회 시험은 위 초점 수정 전의 결과다. 아래 후속 2회는 수정된 코드로 실제 실행한 결과다.

## 3. 수정 후 초점·후속 동작 연속 시험

초점 탐색 조건은 ±0.05 mm, 기본 간격 0.01 mm, settle 0.1초였다. 적응 세분화가 추가되어 각 탐색은 **43개 측정점**을 기록했다.

첫 순서:

`Center → 합성 신호로 실제 Z 탐색 → Set local home → Home → Go to local home → Run → 4구간 중 Stop run → Resume → 완료`

두 번째 순서:

`Go to local home → 같은 조건으로 초점 재확인 → Home → Go to local home → Run → 완료`

이 두 순서 사이에는 서버 재시작이나 장비 재연결을 하지 않았다. 두 번째 초점 재확인 후에는 Set local home을 다시 누르지 않아, 보정된 Z 기준이 후속 이동에 유지되는지도 확인했다.

| 확인 항목 | 결과 |

| 첫 초점 탐색 | best offset +0.0200229 mm, 최종 제어기 raw Z +0.02000 mm |

이 시험은 합성 신호를 이용한 제어 흐름과 실제 이동의 결합 시험이다. 실제 카메라 영상·광학 초점 정확도·레이저 가공 품질을 검증한 결과가 아니다. Wide/Narrow 전체 기본 범위, 자동 XY 재초점 및 Spiral survey 전체를 각각 실기로 다시 완주한 결과로 확대해석하지 않는다.

## 5. 기록 위치와 해석

개발 폴더의 `research/verification/line-workflow-repeat-20261028/`:

- `segments.csv`: 최초 4회·20구간의 시작/완료 시각, 구간 시간, raw 목표.
- 각 job ID 폴더 `records.json`: 서버가 기록한 전체 구간 이벤트. `latest.json`은 상태 관찰값.
- `timeline.jsonl`: 최초 반복 시험 중 실시간 상태. `cycle1-*`, `cycle2-*`는 단계 종료 진단.
- `focus-substitute/events.csv`: 초점 후 2회의 전체 실행 이벤트. 정지·재개를 숨기지 않고 보존했다.
- `focus-substitute/signal.jsonl`, `commands.jsonl`: 합성 신호 측정과 실제 명령 전송 기록. 수정 전 시험도 포함한다.
- `focus-substitute/*-before-fix.jsonl`, `02-focus-result.json`: 실패 재현 증거.
- `focus-substitute/04-focus-corrected.json`, `10-focus2.json`: 43개 측정점과 실제 종료 위치.
- `audit.json`, `focus-substitute/audit.json`: 기록의 누락·실행 형태·좌표 유지 검증.
- `regression-tests-final.txt`: 최종 94개 검사 결과.
- `original-preservation-check.json`, `final-source-sha256.json`: 원본 보존 및 최종 코드 해시.

기록의 시각은 UTC이며 한국 시간은 +9시간이다. Run 경과 시간에는 일시정지 대기가 포함된다. 상태 폴링 직후의 캐시 위치와 뒤이어 읽은 진단 TP는 측정 시각이 달라 마지막 이동 직후 잠깐 차이가 날 수 있다. 도착 판정은 완료 상태와 MD/TP 진단을 함께 확인했다.

시험 전용 8774/8775 서버는 종료했고, 합성 신호를 주입하지 않은 개발 서버 8773을 실행 중이다. 합성 신호로 얻은 +0.02 mm를 실제 초점으로 남기지 않도록 마지막에 일반 웹앱에서 Center → Set local home으로 기계 기준을 복원했다. 최종 raw XYZ는 모두 0, local은 `(12.5,12.5,0)`, 모터 ON·이동 완료·오류 없음 상태다. `final-normal-ready.json` 및 `final-normal-ready.png`에 기록했다. 실제 가공 전 필요한 광학 초점은 사용자가 다시 맞춰야 한다.
