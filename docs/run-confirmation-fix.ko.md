# Run on machine 실행 확인창 수정 — 2026-10-28

## 증상과 확인한 범위

사용자는 Run on machine을 눌렀을 때 600초대 시간이 보이고 확인창이 보이지 않거나 클릭할 수 없다고 보고했다. 기존 구현은 `window.confirm()`이 true를 반환한 뒤에만 `/api/run/start`를 호출했다. 따라서 브라우저 기본 확인창이 처리되지 않으면 서버 실행 요청에 도달하지 않는다. 사용자가 겪은 당시 창 상태를 직접 확보하지 못했으므로 브라우저 자체의 고장 원인까지 확정한 것은 아니다.

표시 시간은 이동 거리와 지정 속도로 계산한 전체 계획 시간의 합계다. 렌더링이나 시작 전 대기 시간이 아니다. 이전 Blade 계획과 이번 UI 검증의 값은 526구간, 684.589초다.

## 변경

- Run on machine / Resume 확인을 브라우저 기본 팝업에서 페이지 내부 `<dialog>`로 변경했다. 시작·취소, 실제 장비/Dry run, 구간 수, 초와 분 단위 계획 시간을 표시한다.
- 취소와 Escape는 실행 요청을 보내지 않는다. 초기 키보드 포커스는 취소 버튼이다.
- 확인 대기와 시작 요청 동안 중복 요청을 막고, 방향키가 Jog 명령으로 전달되지 않게 했다. 기존 Space E-STOP 동작은 유지한다.
- 요청 중·취소·시작 실패 상태를 Run 버튼 옆에 표시한다. 확인 중 도면 또는 연결 모드가 바뀌면 재확인을 요구한다.
- Center 이후 정렬이 필요한 경우 Run 버튼 아래에 차단 사유를 표시한다. 해당 인터록이나 실제 좌표 기준은 변경하지 않았다.
- 정적 파일 버전을 갱신했다. 이미 열려 있는 기존 Chrome 탭은 새로고침해야 새 JavaScript를 사용한다. 서버 재시작은 필요 없다.

## 검증

`research/verification/run-confirmation-20261028/serve_dry_run.py`로 실제 앱을 별도 8771 포트에서 실행했다. 이 프로세스는 실제 시리얼 포트 열기·제어기 링크 검사·카메라 연결을 예외로 차단한다. 브라우저 버튼으로만 실행을 시작했으며 실제 장비 시험이 아니다. Dry run은 실제 이동 시간을 재현하지 않는다.

- Blade 원본 도면을 Open path로 읽어 526구간·684.6초의 확인창이 중앙에 보이고 버튼이 클릭 가능한지 확인했다. `confirmation.png`에 저장했다.
- 방향키 입력 후 취소: `/api/run/start` 및 `/api/jog/move` 요청 0건. `after-cancel.json`.
- Escape 취소 후 시작 버튼 더블 클릭: 시작 요청 1건, 526/526 완료. `run-01.json`.
- 다음 시작 요청에 HTTP 500을 주입: `Start failed: Injected start failure`가 버튼 옆에 보였다. 다음 정상 시작은 전체 완료됐다.
- 이후 부분 실행을 Stop run으로 중단하고 Resume 확인창에서 남은 519구간과 약 677.0초를 표시하는지 확인했다. 시작 후 남은 519개 구간의 완료 이벤트와 `done=true`를 확인했다. `after-stop.json`, `final-state.json`. 이는 재개 UI의 검증이며 실제 장비 중단·재개 안전성 검증은 아니다.
- JavaScript 모듈 문법 검사 통과. 기존 `test_run_records`, `test_sensor_home`, `test_axis_direction` 30개 통과. 초기 제한 환경의 소켓/임시 파일 접근 오류 후 정상 권한에서 재실행해 통과했다.

## 실제 8768 상태

8768 서버에서 새 HTML/JavaScript와 차단 사유 표시를 확인했다. 당시 실제 연결은 Live였지만 실행은 정지 상태였고 Center 이후 `alignmentRequired=true`였다. 시료 정렬과 올바른 도면 중심 좌표 등록이 필요하다. 이 검증에서 실제 장비 실행·Jog·Home·원점 재등록·연결 변경은 하지 않았다. `actual-8768-status.json`, `actual-8768.png`.

실제 장비가 이 수정 후 도면을 끝까지 움직인다는 검증과는 구분해야 한다. 이번 변경은 확인창과 시작 요청 UI에 한정되며 기존 실행기의 중단·재개, 경로 정확도 및 장비 안전성에 대한 별도 평가를 대체하지 않는다.

## 이후 사용자 확인에 따른 좌표 등록

사용자가 현재 위치가 시료의 도면 중심(X/Y)과 초점 기준(Z)에 맞으며 이 위치를 기준으로 등록하라고 명시했다. 실제 서버가 정지 상태이고 자동 초점이 비활성임을 확인한 후 `/api/jog/set-local-home`으로 현재 위치를 `(12.5,12.5,0)`에 대응시켰다. 이 함수는 소프트웨어 오프셋만 바꾸고 시리얼 명령을 보내지 않는다. `alignmentRequired=false`와 Run 버튼 활성화를 확인했다. `user-confirmed-reference.json`.

실제 8768에서 Run 버튼을 눌러 LIVE 표시, 526구간, 684.6초, 실제 장비 시작 버튼이 보이는 것까지 확인하고 취소했다. 실제 시작 버튼은 누르지 않았고, 서버 실행 상태는 `running=false,total=0`이었다. `live-confirmation-after-reference.png`. 따라서 앞 절의 정렬 필요 상태는 등록 이전의 기록이며 이 확인 이후에는 해제되었다.
